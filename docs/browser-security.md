# Защита браузерных запросов (A6)

В production меняющие состояние запросы с `session` cookie (`POST`, `PATCH`, `PUT`, `DELETE` под `/api/`) принимаются только с `Origin`, равным origin фиксированного `WEB_PUBLIC_URL`. Проверка не доверяет `Host` и `X-Forwarded-*`. Отсутствующий, `null` или чужой `Origin` даёт 403 до выполнения действия. Браузерный UI использует same-origin `fetch`; OAuth callback остаётся GET и проверяет отдельный `state`.

При смене публичного домена обновлять `WEB_PUBLIC_URL` и `DISCORD_REDIRECT_URI` вместе с настройкой OAuth. После выкладки проверить вход, сохранение настроек, отправку сообщения и logout. Ручной API-клиент с session cookie обязан передавать `Origin: https://<публичный-домен>`; отсутствие cookie оставляет штатную проверку авторизации маршрута.

Публичные `/api/healthz` и `/api/readyz` в production содержат только общий `status` и код 200/503. Подробная диагностика доступна на `/api/internal/diagnostics/{guildId}` только владельцу/Administrator разрешённого сервера. Заголовки `nosniff`, запрет встраивания, Referrer-Policy и HSTS выставляет приложение; внешний TLS-прокси надо проверить отдельно командой `curl -I` с публичного адреса. Широкая CSP пока в режиме `Report-Only`, чтобы сначала увидеть потребности PrimeReact и медиа на реальном сайте; запрет `frame-ancestors` действует сразу.
